以下の設計を推奨します。
`ABMCTSExplorer` は **探索エンジン本体**ではなく、`ABMCTSM` / `ABMCTSA` / Multi-LLM AB-MCTS を切り替える **汎用オーケストレーター**として設計します。

添付の TreeQuest 仕様では、`ABMCTSA` / `ABMCTSM`、`step`、`ask_batch` / `tell`、複数 action、LLM を node generator として使う構成、`[0, 1]` 正規化 score が前提になっているため、この設計はそれに合わせています。

---

## 1. 設計方針の選択肢

1. Adapter + Strategy パターンで単一 `ABMCTSExplorer` に統合（推奨度：⭐⭐⭐⭐⭐）

   * 理由: `ABMCTSM` / `ABMCTSA` / 独自軽量 MCTS / Multi-LLM を同じ API で扱える。今回の要件に最も合う。

2. `ABMCTSMExplorer` と `ABMCTSAExplorer` を別クラスに分ける（推奨度：⭐⭐⭐）

   * 理由: 実装は単純だが、go wide / go deep の動的切り替えが弱くなる。

3. TreeQuest API をそのまま薄くラップする（推奨度：⭐⭐⭐⭐）

   * 理由: 実装コストは低い。ただし LLM 呼び出し、評価、ログ、checkpoint、切り替え制御が散らばりやすい。

4. 独自 AB-MCTS を完全実装する（推奨度：⭐⭐）

   * 理由: 自由度は高いが、検証コストが高い。現時点では過剰。

5. Actor / Queue ベースの大量並列探索エンジンにする（推奨度：⭐⭐⭐⭐）

   * 理由: ABMCTSA 系・大量中間ステップには強い。ただし基本探索制御にはやや重い。

6. `ExplorerPreset` 中心の設定駆動クラスにする（推奨度：⭐⭐⭐⭐⭐）

   * 理由: `go_wide` / `go_deep` / `hybrid` を設定だけで切り替えられる。Adapter + Strategy と併用するのが最適。

**採用案:**
`1. Adapter + Strategy` を中核にし、`6. ExplorerPreset` で運用しやすくする構成が最適です。

## 3. モード定義

### 1. 基本の探索制御

ABMCTSM / Multi-LLM AB-MCTS 系。

```python
SearchProfile.GO_DEEP
```

用途:

```text
- 高品質な解を少数深く改善する
- 評価を慎重に行う
- LLM judge や複数モデル評価を使う
- batch_size は小さめ
- ask_batch / tell を基本にする
```

### 2. 軽い探索・大量並列・中間ステップ

ABMCTSA 系、または独自軽量 AB-MCTS。

```python
SearchProfile.GO_WIDE
```

用途:

```text
- 多数の候補を並列生成する
- 中間解を大量に作る
- 安価な scorer を使う
- action 数を多めにする
- batch_size は LLM サーバの許容範囲で大きくする
```

### 3. ハイブリッド

```python
SearchProfile.HYBRID
```

流れ:

```text
1. ABMCTSA / 軽量探索で go wide
2. top_k 候補を抽出
3. ABMCTSM / Multi-LLM AB-MCTS で go deep
```

# 6. ActionSpec

`ActionSpec` は、探索木の枝を伸ばすための「行動」です。
Multi-LLM AB-MCTS では、`model` や `prompt_builder` の違いを action として扱います。

```python
@dataclass
class ActionSpec(Generic[StateT]):
    name: str

    # 直接 generator を渡す場合
    generator: NodeGenerator[StateT] | None = None

    # LLM action として使う場合
    model: str | None = None
    prompt_builder: PromptBuilder[StateT] | None = None
    parser: StateParser[StateT] | None = None
    scorer: StateScorer[StateT] | None = None

    temperature: float = 0.7
    max_tokens: int = 2048
    enabled: bool = True
    tags: set[str] = field(default_factory=set)
    llm_kwargs: dict[str, Any] = field(default_factory=dict)

    def run_sync(
        self,
        parent_state: StateT | None,
        context: ExplorerContext,
    ) -> GenerationResult[StateT]:
        if self.generator is not None:
            result = self.generator(parent_state, context)
            if inspect.isawaitable(result):
                raise RuntimeError(
                    f"Action {self.name} is async. Use run_async / ASYNC_ASK_TELL."
                )
            return result

        if not all([self.model, self.prompt_builder, self.parser, self.scorer]):
            raise ValueError(
                f"Action {self.name} requires either generator or "
                "model + prompt_builder + parser + scorer."
            )

        messages = self.prompt_builder(parent_state, context)
        raw = call_llamas_server(
            model=self.model,
            messages=messages,
            temperature=self.temperature,
            max_tokens=self.max_tokens,
            **self.llm_kwargs,
        )

        state = self.parser(raw, parent_state, context)
        score = self.scorer(state, parent_state, context)

        return GenerationResult(
            state=state,
            score=score,
            metadata={
                "action": self.name,
                "model": self.model,
                "raw_response": raw,
            },
        )

    async def run_async(
        self,
        parent_state: StateT | None,
        context: ExplorerContext,
    ) -> GenerationResult[StateT]:
        if self.generator is not None:
            result = self.generator(parent_state, context)
            if inspect.isawaitable(result):
                return await result
            return result

        # call_llamas_server が同期関数なので thread に逃がす。
        return await asyncio.to_thread(self.run_sync, parent_state, context)
```

```python
@dataclass
class TreeQuestBackend(Generic[StateT]):
    algorithm_kind: AlgorithmKind
    algo_kwargs: dict[str, Any] = field(default_factory=dict)

    def __post_init__(self) -> None:
        import treequest as tq

        self._tq = tq
        self.algo = self._build_algo()
        self.name = self.algorithm_kind.value

    def _build_algo(self) -> Any:
        tq = self._tq

        if self.algorithm_kind == AlgorithmKind.ABMCTSA:
            return tq.ABMCTSA(**self.algo_kwargs)

        if self.algorithm_kind == AlgorithmKind.ABMCTSM:
            return tq.ABMCTSM(**self.algo_kwargs)

        if self.algorithm_kind == AlgorithmKind.STANDARD_MCTS:
            return tq.StandardMCTS(**self.algo_kwargs)

        raise ValueError(f"Unsupported TreeQuest algorithm: {self.algorithm_kind}")

    def init_tree(self) -> Any:
        return self.algo.init_tree()

    def step(
        self,
        tree: Any,
        generate_fns: dict[str, Callable[[StateT | None], tuple[StateT, float]]],
    ) -> Any:
        return self.algo.step(tree, generate_fns)

    def ask_batch(
        self,
        tree: Any,
        batch_size: int,
        actions: list[str],
    ) -> tuple[Any, list[Any]]:
        return self.algo.ask_batch(tree, batch_size, actions)

    def tell(
        self,
        tree: Any,
        trial_id: Any,
        result: tuple[StateT, float],
    ) -> Any:
        return self.algo.tell(tree, trial_id, result)

    def top_k(
        self,
        tree: Any,
        k: int,
    ) -> list[tuple[StateT, float]]:
        return self._tq.top_k(tree, self.algo, k=k)

    def is_tree_compatible_with(self, other: SearchBackend[StateT]) -> bool:
        """
        保守的に同一 backend 種別のみ互換とみなす。

        ABMCTSA <-> ABMCTSM の tree 互換性はライブラリ実装に依存するため、
        実運用では小さな探索木で互換性テストを通してから許可する。
        """
        return getattr(other, "name", None) == self.name
```

# 10. ABMCTSExplorer 本体

```python
class ABMCTSExplorer(Generic[StateT]):
    def __init__(
        self,
        *,
        task: str,
        actions: list[ActionSpec[StateT]],
        config: ExplorerConfig,
        backend: SearchBackend[StateT] | None = None,
    ) -> None:
        if not actions:
            raise ValueError("At least one ActionSpec is required.")

        self.task = task
        self.config = config
        self.actions: dict[str, ActionSpec[StateT]] = {
            action.name: action for action in actions
        }

        self.backend: SearchBackend[StateT] = backend or TreeQuestBackend(
            algorithm_kind=config.algorithm_kind,
            algo_kwargs=config.algo_kwargs,
        )

        self.tree = self.backend.init_tree()
        self.step_index = 0
        self.history: list[dict[str, Any]] = []

    def reset(self) -> None:
        self.tree = self.backend.init_tree()
        self.step_index = 0
        self.history.clear()

    def active_actions(self) -> dict[str, ActionSpec[StateT]]:
        return {
            name: action
            for name, action in self.actions.items()
            if action.enabled
        }

    def _context(self) -> ExplorerContext:
        return ExplorerContext(
            task=self.task,
            step_index=self.step_index,
            profile=self.config.profile,
            metadata=self.config.metadata,
        )

    def _validate_score(self, score: float) -> None:
        if not self.config.validate_score_range:
            return

        if not 0.0 <= score <= 1.0:
            raise ValueError(
                f"Score must be normalized to [0, 1], got {score}."
            )

    def _make_generate_fns(
        self,
    ) -> dict[str, Callable[[StateT | None], tuple[StateT, float]]]:
        context = self._context()
        generate_fns: dict[str, Callable[[StateT | None], tuple[StateT, float]]] = {}

        for name, action in self.active_actions().items():

            def generate(
                parent_state: StateT | None,
                _action: ActionSpec[StateT] = action,
            ) -> tuple[StateT, float]:
                result = _action.run_sync(parent_state, context)
                self._validate_score(result.score)
                return result.state, result.score

            generate_fns[name] = generate

        return generate_fns

    def step(self, n: int = 1) -> None:
        """
        TreeQuest の step API をそのまま使う実行方式。
        小規模・同期探索向け。
        """
        if n <= 0:
            return

        for _ in range(n):
            generate_fns = self._make_generate_fns()
            self.tree = self.backend.step(self.tree, generate_fns)
            self.step_index += 1
            self._record_event("step", {"n": 1})

    def ask_tell_batch(self, batch_size: int | None = None) -> None:
        """
        ask_batch / tell によるバッチ探索。
        ABMCTSM では step よりこちらを優先する。
        """
        batch_size = batch_size or self.config.batch_size
        actions = list(self.active_actions().keys())

        if not actions:
            raise ValueError("No active actions.")

        self.tree, trials = self.backend.ask_batch(
            self.tree,
            batch_size,
            actions,
        )

        context = self._context()

        for trial in trials:
            action = self.actions[trial.action]
            result = action.run_sync(trial.parent_state, context)
            self._validate_score(result.score)

            self.tree = self.backend.tell(
                self.tree,
                trial.trial_id,
                (result.state, result.score),
            )

            self.step_index += 1

        self._record_event(
            "ask_tell_batch",
            {
                "batch_size": batch_size,
                "num_trials": len(trials),
            },
        )

    async def ask_tell_batch_async(self, batch_size: int | None = None) -> None:
        """
        大量並列向け。
        ABMCTSA / 独自軽量 AB-MCTS で使う。
        """
        batch_size = batch_size or self.config.batch_size
        actions = list(self.active_actions().keys())

        if not actions:
            raise ValueError("No active actions.")

        self.tree, trials = self.backend.ask_batch(
            self.tree,
            batch_size,
            actions,
        )

        context = self._context()

        async def run_trial(trial: Any) -> tuple[Any, GenerationResult[StateT]]:
            action = self.actions[trial.action]
            result = await action.run_async(trial.parent_state, context)
            return trial, result

        tasks = [asyncio.create_task(run_trial(trial)) for trial in trials]

        for task in asyncio.as_completed(tasks):
            trial, result = await task
            self._validate_score(result.score)

            self.tree = self.backend.tell(
                self.tree,
                trial.trial_id,
                (result.state, result.score),
            )

            self.step_index += 1

        self._record_event(
            "ask_tell_batch_async",
            {
                "batch_size": batch_size,
                "num_trials": len(trials),
            },
        )

    def run(self, budget: int | None = None) -> list[tuple[StateT, float]]:
        """
        同期実行。
        """
        budget = budget or self.config.budget
        consumed = 0

        while consumed < budget:
            remaining = budget - consumed

            if self.config.execution_mode == ExecutionMode.STEP:
                self.step(1)
                consumed += 1

            elif self.config.execution_mode == ExecutionMode.ASK_TELL:
                batch = min(self.config.batch_size, remaining)
                self.ask_tell_batch(batch)
                consumed += batch

            else:
                raise RuntimeError(
                    "ASYNC_ASK_TELL requires run_async()."
                )

        return self.best(self.config.best_k)

    async def run_async(
        self,
        budget: int | None = None,
    ) -> list[tuple[StateT, float]]:
        """
        非同期実行。
        """
        budget = budget or self.config.budget
        consumed = 0

        while consumed < budget:
            remaining = budget - consumed

            if self.config.execution_mode == ExecutionMode.STEP:
                await asyncio.to_thread(self.step, 1)
                consumed += 1

            elif self.config.execution_mode == ExecutionMode.ASK_TELL:
                await asyncio.to_thread(
                    self.ask_tell_batch,
                    min(self.config.batch_size, remaining),
                )
                consumed += min(self.config.batch_size, remaining)

            elif self.config.execution_mode == ExecutionMode.ASYNC_ASK_TELL:
                batch = min(self.config.batch_size, remaining)
                await self.ask_tell_batch_async(batch)
                consumed += batch

            else:
                raise ValueError(f"Unknown execution mode: {self.config.execution_mode}")

        return self.best(self.config.best_k)

    def best(self, k: int = 1) -> list[tuple[StateT, float]]:
        return self.backend.top_k(self.tree, k=k)

    def switch_config(
        self,
        new_config: ExplorerConfig,
        *,
        preserve_tree: bool = True,
    ) -> None:
        """
        go_wide / go_deep / balanced の切り替え。

        同一 backend 種別なら tree を維持する。
        backend 種別が変わる場合は、互換性が保証される場合だけ維持する。
        """
        new_backend = TreeQuestBackend(
            algorithm_kind=new_config.algorithm_kind,
            algo_kwargs=new_config.algo_kwargs,
        )

        if preserve_tree and self.backend.is_tree_compatible_with(new_backend):
            self.backend = new_backend
            self.config = new_config
            return

        # 安全側: tree 非互換なら reset。
        # 実運用で top_k reseed したい場合は別メソッドで明示的に行う。
        self.backend = new_backend
        self.config = new_config
        self.tree = self.backend.init_tree()
        self.step_index = 0

    def _record_event(self, event_type: str, payload: dict[str, Any]) -> None:
        self.history.append(
            {
                "event_type": event_type,
                "step_index": self.step_index,
                "profile": self.config.profile.value,
                "algorithm": self.config.algorithm_kind.value,
                "payload": payload,
            }
        )
```

def simple_scorer(

    """
    仮 scorer。
    実運用では LLM judge / rule-based / test execution / human preference などに差し替える。
    """
    text = state.answer.strip()

    if not text:
        return 0.0

    # 長すぎる回答を少し抑制しつつ、最低限の内容量を見る例。
    length_score = min(len(text) / 2000, 1.0)
    structure_score = 1.0 if "```" in text or "#" in text else 0.7

    return max(0.0, min((length_score * 0.7) + (structure_score * 0.3), 1.0))
````

# 12. 実運用での推奨プリセット

1. `go_deep`: ABMCTSM / Multi-LLM AB-MCTS（推奨度：⭐⭐⭐⭐⭐）

   * 理由: 本命回答を磨く用途に強い。高品質 scorer と相性が良い。

2. `go_wide`: ABMCTSA / 軽量 AB-MCTS（推奨度：⭐⭐⭐⭐⭐）

   * 理由: 大量候補生成、中間ステップ生成、安価な探索に強い。

3. `balanced`: ABMCTSA + ask_tell（推奨度：⭐⭐⭐⭐）

   * 理由: 最初の標準設定として安全。軽量で扱いやすい。

4. `hybrid`: go_wide → top_k → go_deep（推奨度：⭐⭐⭐⭐⭐）

   * 理由: 実務では最も堅い。最初に探索空間を広げ、最後に品質を詰められる。

5. `custom_light`: 独自軽量探索（推奨度：⭐⭐⭐）

   * 理由: TreeQuest 依存を減らせるが、品質検証が必要。

6. `standard_mcts`: 比較用 baseline（推奨度：⭐⭐⭐）

   * 理由: AB-MCTS の効果検証や A/B テスト用に残す価値がある。

**最有力は 1, 2, 4 です。**
つまり、通常運用は `hybrid`、品質重視は `go_deep`、大量候補生成は `go_wide` にします。

# 13. この設計で満たすこと

```text
要件1: 基本の探索制御
→ AlgorithmKind.ABMCTSM + SearchProfile.GO_DEEP で対応。

要件2: 軽い探索・大量並列・中間ステップ
→ AlgorithmKind.ABMCTSA + SearchProfile.GO_WIDE で対応。

柔軟な切り替え
→ switch_config() と ExplorerPreset で対応。

Multi-LLM AB-MCTS
→ ActionSpec を model / prompt / scorer 単位で複数登録して対応。

LLM 呼び出し
→ call_llamas_server() に集約。

汎用性
→ StateT Generic、ActionSpec、SearchBackend Protocol により、回答生成以外にも使える。
```

## 最終推奨構成

```text
ABMCTSExplorer
  - 汎用探索オーケストレーター

SearchBackend
  - TreeQuestBackend
  - CustomLightBackend

ActionSpec
  - LLM action
  - refine action
  - judge action
  - decompose action
  - verify action

ExplorerPreset
  - go_wide
  - go_deep
  - balanced
  - hybrid

この形にしておくと、`ABMCTSM / Multi-LLM AB-MCTS` と `ABMCTSA / 軽量大量並列探索` を、実装を分断せずに同じ探索エンジンとして扱えます。
