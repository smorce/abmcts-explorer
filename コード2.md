はい。
この場合は **`SearchProfile` を LLM に直接選ばせるのではなく、`ProfileDecider` というメタ制御器に判断させる**のがよいです。

結論は以下です。

```text
長時間自律作業では、
最初は GO_WIDE 寄り、
候補・方針・リスクが見えてきたら GO_DEEP 寄り、
停滞・不確実性・分岐不足が出たら GO_WIDE に戻す。
```

TreeQuest 側も `ABMCTSA` / `ABMCTSM`、複数 action、`ask_batch` / `tell`、score `[0, 1]` 正規化、batch 実行を前提にしているため、このメタ判断層を挟む設計と相性が良いです。

---

# 1. 判断方式の選択肢

1. ルールベースで判断する（推奨度：⭐⭐⭐⭐）

   * 理由: 安定する。長時間自律作業で暴走しにくい。ただし柔軟性は限定的。

2. LLM に完全判断させる（推奨度：⭐⭐）

   * 理由: 柔軟だが、判断が揺れやすい。探索ログを都合よく解釈する危険がある。

3. ルールベース + LLM 補助判断（推奨度：⭐⭐⭐⭐⭐）

   * 理由: 最も堅い。数値指標で安全に制御しつつ、LLM に「なぜ wide/deep すべきか」を補助判断させられる。

4. 固定スケジュールで切り替える（推奨度：⭐⭐⭐）

   * 理由: 実装は簡単。例: 最初 30% は wide、残りは deep。ただしタスク状態に追従できない。

5. bandit 的に `GO_WIDE` / `GO_DEEP` を腕として選ぶ（推奨度：⭐⭐⭐⭐）

   * 理由: 実験的には有力。ただし実装と評価設計が少し難しい。

6. 階層型にする。上位が profile、下位が action を選ぶ（推奨度：⭐⭐⭐⭐⭐）

   * 理由: 長時間自律作業に最適。`GO_WIDE` / `GO_DEEP` の判断と、生成・批評・検証・修正 action の判断を分離できる。

**採用案:**
`3. ルールベース + LLM 補助判断` を基本にし、将来的に `6. 階層型` に拡張するのがよいです。

```python
    RESOURCE_PRESSURE = "resource_pressure"
```

```text
judge_disagreement:

  最近の best score 改善量。小さいなら plateau。
```

# 5. ルールベース ProfileDecider

```python
@dataclass(frozen=True)
class ProfileDeciderConfig:
    min_initial_nodes: int = 30
    min_diversity_score: float = 0.45
    high_uncertainty_threshold: float = 0.60
    high_judge_disagreement_threshold: float = 0.50

    strong_candidate_score: float = 0.82
    top_k_convergence_std: float = 0.08

    plateau_steps_threshold: int = 3
    low_recent_improvement: float = 0.01

    late_budget_ratio: float = 0.30

    # profile が頻繁に揺れるのを防ぐ
    min_epochs_before_switch: int = 2
    switch_confidence_threshold: float = 0.60


class RuleBasedProfileDecider:
    def __init__(self, config: ProfileDeciderConfig | None = None) -> None:
        self.config = config or ProfileDeciderConfig()
        self._last_profile: SearchProfile | None = None
        self._epochs_since_switch: int = 999

    def decide(
        self,
        diagnostics: SearchDiagnostics,
        current_profile: SearchProfile,
    ) -> ProfileDecision:
        cfg = self.config

        wide_score = 0.0
        deep_score = 0.0
        reasons: list[ProfileDecisionReason] = []

        # 1. 初期は広げる
        if diagnostics.total_nodes < cfg.min_initial_nodes:
            wide_score += 0.35
            reasons.append(ProfileDecisionReason.EARLY_EXPLORATION)

        # 2. 多様性が低いなら広げる
        if diagnostics.diversity_score < cfg.min_diversity_score:
            wide_score += 0.30
            reasons.append(ProfileDecisionReason.INSUFFICIENT_DIVERSITY)

        # 3. 不確実性が高いなら広げる
        if diagnostics.uncertainty_score >= cfg.high_uncertainty_threshold:
            wide_score += 0.25
            reasons.append(ProfileDecisionReason.HIGH_UNCERTAINTY)

        # 4. judge disagreement が高いなら、まだ深掘りしすぎない
        if diagnostics.judge_disagreement >= cfg.high_judge_disagreement_threshold:
            wide_score += 0.20
            reasons.append(ProfileDecisionReason.HIGH_UNCERTAINTY)

        # 5. 強い候補があり、top-k が収束しているなら深掘り
        if (
            diagnostics.best_score >= cfg.strong_candidate_score
            and diagnostics.top_k_score_std <= cfg.top_k_convergence_std
        ):
            deep_score += 0.40
            reasons.append(ProfileDecisionReason.STRONG_CANDIDATE_FOUND)

        # 6. 残り予算が少ないなら深掘り・検証に寄せる
        if diagnostics.remaining_budget_ratio <= cfg.late_budget_ratio:
            deep_score += 0.30
            reasons.append(ProfileDecisionReason.LATE_STAGE_REFINEMENT)

        # 7. 改善が止まっている場合
        if (
            diagnostics.plateau_steps >= cfg.plateau_steps_threshold
            and diagnostics.score_improvement_recent <= cfg.low_recent_improvement
        ):
            # 浅い段階の plateau は探索不足なので wide
            if diagnostics.max_depth <= 2:
                wide_score += 0.25
            # 深い段階の plateau は検証・精緻化不足なので deep
            else:
                deep_score += 0.25
            reasons.append(ProfileDecisionReason.PLATEAU)

        if wide_score > deep_score:
            next_profile = SearchProfile.GO_WIDE
            confidence = min(1.0, 0.5 + wide_score - deep_score)
        else:
            next_profile = SearchProfile.GO_DEEP
            confidence = min(1.0, 0.5 + deep_score - wide_score)

        # ヒステリシス: 頻繁な切り替え防止
        if (
            next_profile != current_profile
            and self._epochs_since_switch < cfg.min_epochs_before_switch
        ):
            next_profile = current_profile
            confidence = 0.50

        if confidence < cfg.switch_confidence_threshold:
            next_profile = current_profile

        if next_profile != current_profile:
            self._epochs_since_switch = 0
        else:
            self._epochs_since_switch += 1

        suggested_batch_size = self._suggest_batch_size(next_profile, diagnostics)

        return ProfileDecision(
            profile=next_profile,
            confidence=confidence,
            reasons=reasons,
            explanation=(
                f"wide_score={wide_score:.2f}, "
                f"deep_score={deep_score:.2f}, "
                f"selected={next_profile.value}"
            ),
            suggested_batch_size=suggested_batch_size,
        )

    def _suggest_batch_size(
        self,
        profile: SearchProfile,
        diagnostics: SearchDiagnostics,
    ) -> int:
        if profile == SearchProfile.GO_WIDE:
            if diagnostics.failed_generation_ratio > 0.20:
                return 8
            return 24

        if profile == SearchProfile.GO_DEEP:
            return 5

        return 8
```

# 6. 判断ルールの意味

## `GO_WIDE` を選ぶべき状況

```text
- まだ候補数が少ない
- top-k が似たような候補ばかり
- scorer / judge の不一致が大きい
- 問題の分解が不十分
- 方針が複数ありそう
- 浅い探索で plateau している
- best score は高くないのに、同じ方向の修正を繰り返している
```

```text
- 有望候補がすでにある
- top-k が収束してきた
- 残り budget が少ない
- 回答の構造は決まっており、品質改善・検証・統合が必要
- 不確実性が局所化している
- 深い依存関係、実装、証明、設計詳細を詰める段階に入った
```

```python
class HybridProfileDecider:
    def __init__(
        self,
        rule_decider: RuleBasedProfileDecider,
        use_llm_advice: bool = True,
    ) -> None:
        self.rule_decider = rule_decider
        self.use_llm_advice = use_llm_advice

    def decide(
        self,
        diagnostics: SearchDiagnostics,
        current_profile: SearchProfile,
    ) -> ProfileDecision:
        rule_decision = self.rule_decider.decide(
            diagnostics=diagnostics,
            current_profile=current_profile,
        )

        if not self.use_llm_advice:
            return rule_decision

        # LLM advice は低 confidence のときだけ参照する
        if rule_decision.confidence >= 0.75:
            return rule_decision

        advice = ask_llm_profile_advice(diagnostics, current_profile)

        # LLM と rule が一致したら confidence を少し上げる
        if advice.preferred_profile == rule_decision.profile:
            return ProfileDecision(
                profile=rule_decision.profile,
                confidence=min(1.0, rule_decision.confidence + 0.10),
                reasons=rule_decision.reasons,
                explanation=(
                    rule_decision.explanation
                    + f" | llm_agreed: {advice.reason}"
                ),
                suggested_batch_size=rule_decision.suggested_batch_size,
                suggested_budget=rule_decision.suggested_budget,
            )

        # LLM が反対しても、rule confidence が一定以上なら覆さない
        if rule_decision.confidence >= 0.60:
            return rule_decision

        # ルールも弱く、LLM が高 confidence の場合だけ採用
        if advice.confidence >= 0.75:
            return ProfileDecision(
                profile=advice.preferred_profile,
                confidence=advice.confidence,
                reasons=rule_decision.reasons,
                explanation=f"LLM advice adopted: {advice.reason}",
                suggested_batch_size=(
                    24 if advice.preferred_profile == SearchProfile.GO_WIDE else 5
                ),
            )

        return rule_decision
```

# 8. `ABMCTSExplorer` への統合

`run_autonomous()` を追加します。

```python
@dataclass(frozen=True)
class AutonomousRunConfig:
    total_budget: int = 300
    epoch_budget: int = 25
    diagnostics_top_k: int = 10
    allow_profile_switch: bool = True


class ABMCTSExplorer(Generic[StateT]):
    ...

    def collect_diagnostics(
        self,
        *,
        total_budget: int,
        consumed_budget: int,
        top_k: int = 10,
    ) -> SearchDiagnostics:
        candidates = self.best(k=top_k)

        scores = [score for _, score in candidates]
        best_score = max(scores) if scores else 0.0
        mean_score = sum(scores) / len(scores) if scores else 0.0

        if len(scores) >= 2:
            mean = mean_score
            variance = sum((s - mean) ** 2 for s in scores) / len(scores)
            score_std = variance ** 0.5
        else:
            score_std = 0.0

        # 以下は実装依存。
        # tree から depth / node count を取れるように backend adapter に生やすのが望ましい。
        tree_stats = self.backend.stats(self.tree)

        diversity_score = self.estimate_diversity(candidates)
        uncertainty_score = self.estimate_uncertainty(candidates)
        judge_disagreement = self.estimate_judge_disagreement(candidates)

        return SearchDiagnostics(
            total_nodes=tree_stats.total_nodes,
            max_depth=tree_stats.max_depth,
            avg_depth=tree_stats.avg_depth,
            best_score=best_score,
            top_k_mean_score=mean_score,
            top_k_score_std=score_std,
            score_improvement_recent=self.estimate_recent_improvement(),
            diversity_score=diversity_score,
            uncertainty_score=uncertainty_score,
            judge_disagreement=judge_disagreement,
            plateau_steps=self.estimate_plateau_steps(),
            remaining_budget_ratio=max(
                0.0,
                (total_budget - consumed_budget) / total_budget,
            ),
        )

    async def run_autonomous(
        self,
        *,
        run_config: AutonomousRunConfig,
        profile_decider: HybridProfileDecider,
    ) -> list[tuple[StateT, float]]:
        consumed = 0

        while consumed < run_config.total_budget:
            diagnostics = self.collect_diagnostics(
                total_budget=run_config.total_budget,
                consumed_budget=consumed,
                top_k=run_config.diagnostics_top_k,
            )

            decision = profile_decider.decide(
                diagnostics=diagnostics,
                current_profile=self.config.profile,
            )

            if (
                run_config.allow_profile_switch
                and decision.profile != self.config.profile
            ):
                new_config = self._config_for_decision(decision)
                self.switch_config(
                    new_config,
                    preserve_tree=True,
                )

            epoch_budget = min(
                run_config.epoch_budget,
                run_config.total_budget - consumed,
            )

            if self.config.execution_mode == ExecutionMode.ASYNC_ASK_TELL:
                await self.run_async(budget=epoch_budget)
            else:
                self.run(budget=epoch_budget)

            consumed += epoch_budget

        return self.best(self.config.best_k)

    def _config_for_decision(
        self,
        decision: ProfileDecision,
    ) -> ExplorerConfig:
        if decision.profile == SearchProfile.GO_WIDE:
            return ExplorerConfig(
                algorithm_kind=AlgorithmKind.ABMCTSA,
                profile=SearchProfile.GO_WIDE,
                execution_mode=ExecutionMode.ASYNC_ASK_TELL,
                budget=self.config.budget,
                batch_size=decision.suggested_batch_size or 24,
                best_k=self.config.best_k,
                metadata=self.config.metadata,
            )

        if decision.profile == SearchProfile.GO_DEEP:
            return ExplorerConfig(
                algorithm_kind=AlgorithmKind.ABMCTSM,
                profile=SearchProfile.GO_DEEP,
                execution_mode=ExecutionMode.ASK_TELL,
                budget=self.config.budget,
                batch_size=decision.suggested_batch_size or 5,
                best_k=self.config.best_k,
                algo_kwargs={
                    "max_process_workers": decision.suggested_batch_size or 5,
                },
                metadata=self.config.metadata,
            )

        raise ValueError(f"Unsupported profile: {decision.profile}")
```

# 9. 重要な注意点

`GO_WIDE` / `GO_DEEP` の切り替えで backend が `ABMCTSA` → `ABMCTSM` に変わる場合、探索木の互換性を安易に仮定しない方がよいです。

安全な設計は次のどちらかです。

1. 同一 tree を維持する（推奨度：⭐⭐⭐）

   * 理由: 効率はよい。ただし backend 間の tree 互換性を検証する必要がある。

2. `top_k` の state だけを seed として新しい tree を作る（推奨度：⭐⭐⭐⭐⭐）

   * 理由: 安全。`GO_WIDE` で得た有望候補を `GO_DEEP` の初期候補として渡せる。

3. tree は分けて、global memory に候補を保存する（推奨度：⭐⭐⭐⭐⭐）

   * 理由: 長時間自律作業向き。探索木破損や backend 依存を避けられる。

4. 常に同じ backend で profile だけ変える（推奨度：⭐⭐⭐⭐）

   * 理由: 実装が安全。`ABMCTSA` のまま batch_size/action/scorer を変えて wide/deep 風に運用する。

5. backend 切り替え時に checkpoint を必須化する（推奨度：⭐⭐⭐⭐）

   * 理由: 長時間作業では復旧性が重要。

**推奨:**
長時間自律作業では、`tree` を直接引き継ぐより、`top_k` 候補を `global_candidate_pool` に保存して、次 profile に seed する方式が堅いです。

```python
def simple_profile_policy(d: SearchDiagnostics) -> SearchProfile:
    if d.total_nodes < 30:
        return SearchProfile.GO_WIDE

    if d.diversity_score < 0.45:
        return SearchProfile.GO_WIDE

    if d.uncertainty_score > 0.60:
        return SearchProfile.GO_WIDE

    if d.best_score >= 0.82 and d.top_k_score_std <= 0.08:
        return SearchProfile.GO_DEEP

    if d.remaining_budget_ratio <= 0.30:
        return SearchProfile.GO_DEEP

    if d.plateau_steps >= 3:
        if d.max_depth <= 2:
            return SearchProfile.GO_WIDE
        return SearchProfile.GO_DEEP

    return SearchProfile.GO_WIDE
```

# 11. 実務上の推奨判断

LLM に長時間自律作業をさせる前提なら、**初期値を `GO_WIDE` にして、自律的に `GO_DEEP` へ移行させる**のがよいです。

```text
初期:
  GO_WIDE
  - 多様な方針を出す
  - タスク分解する
  - リスクを洗い出す
  - 複数候補を作る

中盤:
  ProfileDecider が判断
  - 不確実性が高いなら GO_WIDE 継続
  - 有望候補が出たら GO_DEEP

終盤:
  GO_DEEP
  - 統合
  - 検証
  - 反例チェック
  - 品質改善
  - 最終成果物化

停滞時:
  GO_WIDE に戻す
  - 別方針
  - 別モデル
  - 別 prompt
  - 別 scorer
```

# 13. 最終回答

`SearchProfile.GO_WIDE` と `SearchProfile.GO_DEEP` を LLM 自身に判断させたい場合、**LLM に直接 profile を選ばせる設計は避けるべき**です。

代わりに、以下の形にしてください。

```text
ProfileDecider が数値指標で一次判断する。
LLM は補助的に判断理由を出す。
最終決定は ProfileDecider が行う。
切り替えには hysteresis を入れる。
backend をまたぐ場合は tree 直接継承ではなく top_k seed を使う。
```

推奨初期構成はこれです。

```python
profile_decider = HybridProfileDecider(

        ProfileDeciderConfig(
            min_initial_nodes=30,
            min_diversity_score=0.45,
            high_uncertainty_threshold=0.60,
            strong_candidate_score=0.82,
            top_k_convergence_std=0.08,
            plateau_steps_threshold=3,
            late_budget_ratio=0.30,
        )
    ),
    use_llm_advice=True,
)
```

この設計にすると、長時間自律作業中に LLM が次を判断できます。

```text
今は探索空間を広げるべきか？
それとも有望候補を深掘りするべきか？
停滞しているのは探索不足か？
それとも検証・精緻化不足か？
残り budget 的に収束へ向かうべきか？
```

つまり、`GO_WIDE` / `GO_DEEP` は単なる手動設定ではなく、**探索状態に応じて切り替わる自己制御パラメータ**として扱えます。
